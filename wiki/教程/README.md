# EchoMind 源码教程

这套教程以当前 Python 工作区为准，面向知道变量、函数和字典、但还没完整读过 Agent 应用的人。遇到类、异步、向量、工具协议等概念时，正文会结合实际代码解释，不要求你先掌握整套框架。核对日期：2026-10-14。

编号教程和配套附录都在 `wiki/教程/`，终端命令仍在项目根目录执行。教程只关注当前 Python 应用，直接通过 API 和现有测试理解处理过程。

先跑通一条消息，再理解各模块为什么存在、如何接续数据，最后通过实验和测试核对实现。真实模型可能选择不同分类和工具；文中的固定结果会标注教学假设。

## 怎样跟着正文读代码

每一步尽量按下面的顺序展开：

1. **先看具体问题。** 例如第二轮只说“还是不行”，本轮缺的到底是什么信息。
2. **确认输入从哪来。** 参数是HTTP原文、数据库读回值、上一步分类结果，还是模型填的工具参数。
3. **读关键代码并代入值。** 不只记函数名，而是看这几行怎样把reader_01、demo-login和401转成下一种数据。
4. **找到返回点。** 子函数return以后，外面的哪个变量接住它，调用者随后执行什么。
5. **再看变化与失败。** 追问、重试、换任务、超时为什么走不同分支，用例和实验能检查其中哪一部分。

一段代码还看不懂时，先回到本段给出的输入示例，确认当前变量的类型和来源，再对照逐句解释。图和表用于定位关系；过程、数据变化和代码衔接在正文里展开。运行实验前先确认模型、存储与开发依赖的前提。

## 贯穿教程的一条消息

```json
{
  "message": "登录返回 HTTP 401，怎么处理？",
  "user_id": "reader_01",
  "conv_id": "demo-login",
  "client_request_id": "msg-001"
}
```

先假设新用户、新会话，识别为技术登录问题，并由模型提出错误码查询。第03章跟它走到提交；第05章用退款追问说明字段继承；第08章加公司规范；第11章换成固定评测用例。示例服务端编号R1、融合分0.84与路由分1.13分别有自己的来源，不应混成同一概率。

## 实验与代码片段约定

- `python3.12` 的纯标准库实验可独立运行；导入模型/MCP依赖的 `python` 实验，先按第02章准备虚拟环境并安装依赖。
- 第02、04章聊天与第11章评测会请求真实模型；第08章 `/search` 会请求改写模型，并可能请求重排模型。固定输入实验不代表真实模型质量实测。
- HTTP默认访问 `http://localhost:8000`。应用访问身份用客户端变量 `ECHOMIND_TUTORIAL_TOKEN`，管理操作需要admin；不要与模型Key混用。
- 同一消息重试保留客户端ID，新消息更换ID；追问沿用conv_id。要观察空背景，使用新的用户与会话，启用鉴权后用户身份取Token映射。
- 源码节选用于对照已有实现，可能省略函数外围；只有标注实验的完整命令用于直接执行。图表示处理关系，不表示每个框都是独立服务。

## 动手之前，先选环境

刚创建的本地开发环境可以直接跟第 02 章操作。如果已有需要保留的聊天、知识文档或评测基线，先按[附录：使用独立练习环境](附录-接口配置与数据字典.md#tutorial-environment)启动隔离环境。换一个会话编号只能隔离会话记录，不能隔离共享知识库和基线文件。

本教程的终端示例使用 macOS、Linux 或 Windows 的 WSL 中的 Bash/Zsh。PowerShell 的环境变量与多行输入写法不同，请不要直接原样粘贴。Docker 路线不要求宿主机安装 Python；运行本机 Python 实验时使用 Python 3.12。
