# trace 合并版本使用指南

本页描述 trace 分支融合附件 2026 年 10 月更新后的实现。更新说明与原教程保留为历史背景，验收证据见 [本次验证日志](../docs/merge-upstream-2026-10/verification.md)。

## 主请求与能力边界

```text
/chat → API 身份 → 50 秒总预算 + 会话锁 → 回执检查
      → SourceMessage 顺序预留 → 轻量上下文 + 业务状态
      → LLM / Embedding / Pattern 意图融合 → Context Planner
      → 按需获取记忆 / 画像 / 知识 / 经验 / Skills
      → 主辅 Agent + 请求局部工具执行（含标准 MCP）
      → 请求资源清理 → 消息 / 状态 / 回执 / 演化证据原子提交
      → 经验采集与后台记忆维护 → ChatResponse
```

Planner 和 Agent 工具共用请求级检索会话，相同源、查询和 Top-K 复用结果。知识检索保留 Dense/BM25 并行召回、两级 RRF、MMR 和可失败回退的 LLM 重排。工具目录已由 `mcp/` 迁为 `tooling/`，`mcp` 包名留给官方 SDK。

记忆演化只消费原始用户证据；模型回复和未知工具结果不是用户偏好事实。经验采集要求成功完成的业务结果，并继续受经验质量审核与失效机制约束。订单查询、退款执行和实际工单创建仍需要业务系统接入。

## API 与兼容变化

- `/chat` 支持 `client_request_id`：新消息生成新 ID，同一消息重试复用 ID。成功回执重放不重复模型调用、写入、演化入队或经验采集；同一会话同 ID 不同消息返回 409。
- 响应保留 `latency_ms`（Agent 编排耗时）、`trace_id`、`request_duration_ms`（至整轮提交完成的耗时）。`Server-Timing` 包括 HTTP 处理及收尾；回执重放保留原结果及原 Trace ID，本次 HTTP 请求有独立 Span。
- 新增 `status=success/partial/failed`、`retryable`、`error_code`、`intent_embedding_source`。失败回复返回 503，总超时返回 504。已尝试副作用工具但结果不确定时，不允许盲目重放或由兜底 Agent 再做相同操作。
- `knowledge_used` 以实际成功提供知识证据为准，覆盖 Planner 和响应式工具。失败或降级结果不作为正常证据。
- `/eval/run` 返回 202 和 `job_id`，通过 `/eval/jobs/{job_id}` 轮询。Judge 失败的 scores 为空，不用 0.5 填充；只有可比较的完整报告更新基线。任务保存在当前进程，重启后需重提。
- `/integrations/embedding`、`/integrations/mcp`、`/integrations/mcp/call` 用于集成诊断；`/mcp/` 提供标准协议服务。默认 Microsoft Learn 外部连接可用 `MCP_EXTERNAL_ENABLED=false` 关闭。
- `/memory/{user_id}`、事件/状态、经验查询与反馈，以及 OTel 历史/质量回归接口继续保留。

## 身份、轨迹与监控

`ECHOMIND_ENV=production` 必须配置 `ECHOMIND_API_TOKENS`，映射独立 API Token 到 user_id 与 user/admin 角色。开启鉴权后，聊天身份来自 Token，忽略请求体的伪造身份。普通用户只可访问自己的记忆和经验；工具轨迹、集成调试、评测及监控管理需要管理员。

历史 Trace 接口支持 API admin，或仅用于历史路由的 `TRACE_ADMIN_TOKEN`；两者任选其一，不要求同一个 Authorization 匹配两个令牌。历史保存需启用 `TRACE_HISTORY_ENABLED=true`，策略文件由 `TRACE_POLICY_PATH` 指定，默认 `config/observability.yml`。

OTel/SQLite 保存结构化诊断，Redis 保存工具轨迹（7 天，最近列表最多 200 条）。工具轨迹 HTTP 接口和 Redis 中的原始输入值、输出、消息正文和异常文本会被遮蔽。Span 覆盖已埋点主链，并不等于完整程序录像。回执为业务重试保存消息和响应，其数据性质与诊断 Trace 不同。

`requests_total` 在有效 HTTP 聊天入口记录一次；`contextweave_requests_total` 按完成 pipeline 的业务结果分类。Agent 与工具耗时只记录实际执行，周期采集不重复 observe。路由恢复使用最近 300 秒、最多 50 个完成样本，至少 5 个样本才参与降权；恢复探测绑定请求 ID。

## 数据迁移与部署

- 不复制附件的 `.env`、Chroma 数据、Redis 数据或 Git 历史。已有密钥只保留在本地配置中，新增配置参考 `.env.example`。
- 旧 `wm:user:conv` 与 `summary:user:conv` 按需原子迁移为结构化哈希键，并保留 TTL；已存在的新键不覆盖。用户或会话含冒号时，旧键归属有歧义，保留原数据且不自动迁移。此类数据需要管理员依据业务身份单独确认，禁止批量猜测归属。
- 原画像、演化与经验集合保持。消息继续保留 SourceMessage ID/sequence；原子提交将成功回合的两条消息、回执、业务状态与 pending 证据一起写入。
- 知识文档按显式 document_id 或标题身份更新，重新导入会 upsert、删除多余旧片段、刷新 BM25 并使工具缓存失效。同标题不同来源应提供不同 ID。旧知识文档可保留，重新导入时按身份逐步兼容，不要求清库。
- API 端口和存储/监控宿主端口绑定 127.0.0.1；对外服务需配置代理。主服务和 Chroma 健康检查使用 Python，不依赖 curl。readiness 要求完整组件并检查 Redis/Chroma，启动失败也会清理已初始化组件。
- 保留 `docker-compose.observability.yml` 和 `docker-compose.dashboard.yml`。按 [Trace P2](../docs/trace-p2.md)、[Trace P3](../docs/trace-p3.md) 配置 Collector、Grafana 和告警。
- 默认 `PROMETHEUS_PORT=0`，通过受 API 权限保护的 `/metrics` 抓取；开启 API 鉴权后 Prometheus 必须配置管理员采集令牌。见 [鉴权采集示例](教程/examples/prometheus.auth.yml)。不要把独立指标监听端口暴露给不受信任网络。
- `docker-compose.web.yml` 引用独立的 EchoMindFrontend/EchoMindJava，只有具备这些目录时才启动这组服务。本次不包含它们的代码或前端验收。

```bash
docker compose up -d --build
# 显式启用观测叠加时，按现有 Trace 文档配置 OTLP 与服务地址：
docker compose -f docker-compose.yml -f docker-compose.observability.yml -f docker-compose.dashboard.yml config --quiet
```

线上向量服务的权限、额度与费用以平台实际规则为准；代码固定调用 `BAAI/bge-m3`，无 Key 或调用失败时整组回退本地 n-gram。该向量仅用于意图分支，不替换 RAG 的 Chroma 向量空间。

## 验证与中断恢复

```bash
python -m pip install -r requirements-dev.txt
python -m pip check
OTEL_TRACES_EXPORTER=none INTENT_EMBEDDING_PROVIDER=local python -m pytest tests -q
python wiki/教程/scripts/check_docs.py
```

本地 Python 3.10 使用 async-timeout 兼容，Docker 镜像为 Python 3.12。离线测试使用模拟数据库、模型和本地 MCP fixture；不代表真实数据库、在线模型或生产部署已验收。本轮实际结果及环境限制统一写入 [verification.md](../docs/merge-upstream-2026-10/verification.md)。

中断后先读 [progress.md](../docs/merge-upstream-2026-10/progress.md)，核对分支/HEAD/工作区和附件 SHA，再从对应 M0—M5 日志的首个未完成步骤继续。已完成阶段都有独立 Git 检查点，禁止直接重置用户新增修改。
